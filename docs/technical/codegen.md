# SPEC: Codegen

## Responsibility

Read the SQLite database and emit GDScript stub files that game developers
fill in to implement their bindings. Run as an editor tool (not at game
runtime). Validate that existing binding files match the current database
state and raise errors for mismatches.

---

## When to Run

Codegen runs:
1. Manually, via an editor button in the Tarinoi plugin panel.
2. Automatically after a successful sync, if `tarinoi/codegen_on_sync` is
   enabled in ProjectSettings.

Codegen never runs at game runtime.

---

## Output Files

All files are written to `res://demo/bindings/generated/` by default.
The output path is configurable via `tarinoi/codegen_output_path`.

| File | Contents |
|---|---|
| `tarinoi_functions.gd` | One inner class per function collection |
| `tarinoi_variables.gd` | One inner class per variable collection |
| `tarinoi_lists.gd` | Constants for all list option values |
| `tarinoi_entities.gd` | Constants for all entity names |

These files are stubs — they declare the interface but do not implement it.
Game developers copy or subclass them in `demo/bindings/impl/` and fill in
the logic. The generated files should be committed to version control and
regenerated whenever the Tarinoi project changes.

---

## `tarinoi_functions.gd`

One inner class per function collection. Each class has one method stub per
declared function.

```gdscript
# AUTO-GENERATED by Tarinoi codegen. Do not edit manually.
# Regenerate with: Tarinoi → Regenerate Bindings

class_name TarinoiFunctions

class Global:
    ## MyFunnyGate(flag: bool) -> bool
    ## effect: pure
    func MyFunnyGate(flag: Variant) -> Variant:
        push_error("TarinoiFunctions.Global.MyFunnyGate is not implemented")
        return false

class Checks:
    ## SkillCheck(skill: Variant, threshold: Variant) -> bool
    ## effect: side-effect
    func SkillCheck(skill: Variant, threshold: Variant) -> Variant:
        push_error("TarinoiFunctions.Checks.SkillCheck is not implemented")
        return false
```

**Notes:**
- Class names are the collection `collection_name` in PascalCase.
- Method names match `function_name` exactly (Tarinoi names are already
  PascalCase by convention).
- Argument names match `arg_name` from `TArgDeclaration`.
- All arguments are typed `Variant` in the stub because the game receives
  resolved values (the Dispatcher resolves `Ls`, `Var`, `Ent` references
  before calling). The declared `data_type` is included as a comment.
- Return type is `Variant` for the same reason; declared `function_returns`
  is in a comment.
- `push_error` in the body ensures unimplemented stubs are loud.

## `tarinoi_variables.gd`

One inner class per variable collection, implementing the get/set protocol.

```gdscript
# AUTO-GENERATED by Tarinoi codegen. Do not edit manually.

class_name TarinoiVariables

class Player:
    ## Variables in this collection:
    ##   health  (number)  default: 100
    ##   has_keycard  (boolean)  default: false

    func get_variable(variable_name: String) -> Variant:
        push_error("TarinoiVariables.Player.get_variable is not implemented")
        return null

    func set_variable(variable_name: String, value: Variant) -> void:
        push_error("TarinoiVariables.Player.set_variable is not implemented")
```

The variable names and types are listed as comments so the implementor knows
what to handle without consulting Tarinoi. No per-variable methods are
generated — the get/set protocol takes a name string.

---

## `tarinoi_lists.gd`

Constants for all list options, enabling game code to use symbolic names
rather than raw strings when interacting with list values.

```gdscript
# AUTO-GENERATED by Tarinoi codegen. Do not edit manually.

class_name TarinoiLists

class Player:
    class Skills:
        const MECHANICS = "mechanics"
        const RHETORIC  = "rhetoric"
        const EMPATHY   = "empathy"

class Global:
    class Thresholds:
        const TRIVIAL      = "trivial"
        const EASY         = "easy"
        const CHALLENGING  = "challenging"
        const FORMIDABLE   = "formidable"
```

`TarinoiLists.Player.Skills.MECHANICS` is the canonical way for game code
to reference list values. The actual `option_value` (from `TListOptionSpec`)
is stored in the DB and resolved by the Dispatcher at runtime; these constants
match the `key` field.

---

## `tarinoi_entities.gd`

Constants for all entity names, enabling symbolic references in game code.

```gdscript
# AUTO-GENERATED by Tarinoi codegen. Do not edit manually.

class_name TarinoiEntities

class Major:
    const SYLVIA_WHISTLER  = "sylvia_whistler"
    const IRMA             = "irma"

class Supporting:
    const UNNAMED_GUARD    = "unnamed_guard"
```

Constants are the `entity_name` from `TEntity.entity_name`, uppercased with
underscores. Class names are collection `collection_name` in PascalCase.

## Mismatch Validation

Codegen compares the current database state against any previously generated
files. Mismatches are raised as errors in the Godot editor Output panel and
written to a `tarinoi_codegen.log` file in the project root.

### Mismatch Conditions

| Condition | Severity | Message |
|---|---|---|
| Function in DB not in generated file | ERROR | `Missing function: Checks.SkillCheck` |
| Function in generated file not in DB | WARNING | `Obsolete function stub: Checks.OldFunction — remove from impl` |
| Function argument count changed | ERROR | `Argument count mismatch: Checks.SkillCheck (DB: 2, generated: 3)` |
| Function return type changed | WARNING | `Return type changed: Checks.SkillCheck (DB: bool, generated: string)` |
| Variable in DB not in generated file | ERROR | `Missing variable: Player.health` |
| Variable in generated file not in DB | WARNING | `Obsolete variable: Player.old_flag` |
| List option added | WARNING | `New list option: Player.Skills.hacking — regenerate` |
| List option removed | ERROR | `Removed list option: Player.Skills.hacking — may break references` |
| Entity added | WARNING | `New entity: Major.new_character — regenerate` |
| Entity removed | WARNING | `Removed entity: Major.old_character` |
| Collection renamed | ERROR | `Collection renamed: old_name → new_name — update bindings` |

ERRORs block codegen from completing (files are not written).
WARNINGs are logged but codegen proceeds.

### Validation Flow

```
1. Read all TFunctionDeclaration, TVariableDeclaration, TListSpec, TEntity
   documents from SQLite.
2. If generated files exist, parse them (regex/line scan — not full GDScript
   parse, just extract class names and method signatures).
3. Compare. Collect errors and warnings.
4. If errors: log all, abort, do not write files.
5. If warnings only: log all, write files (regenerating updates the stubs).
6. If no issues: write files silently.
```

## Codegen Algorithm

### Querying the Database

```gdscript
# Functions
SELECT payload FROM documents
WHERE document_type = 'function-declaration'
  AND is_tombstone = 0 AND is_archived = 0 AND is_moved = 0
ORDER BY collection_id, json_extract(payload, '$.function_name')

# Variables
SELECT payload FROM documents
WHERE document_type = 'variable-declaration'
  AND is_tombstone = 0 AND is_archived = 0 AND is_moved = 0
ORDER BY collection_id, json_extract(payload, '$.variable_name')

# Lists
SELECT payload FROM documents
WHERE document_type = 'list-spec'
  AND is_tombstone = 0 AND is_archived = 0 AND is_moved = 0
ORDER BY collection_id, json_extract(payload, '$.list_name')

# Entities (only dialog_capable ones are relevant for codegen)
SELECT payload FROM documents
WHERE document_type = 'entity'
  AND json_extract(payload, '$.dialog_capable') = 1
  AND is_tombstone = 0 AND is_archived = 0 AND is_moved = 0
ORDER BY collection_id, json_extract(payload, '$.entity_name')
```

Join with `collections` table to resolve `collection_name` per document.

### Collection Name to Class Name

```gdscript
func collection_to_class_name(name: String) -> String:
    # "player_state" → "PlayerState"
    var parts = name.split("_")
    return "".join(parts.map(func(p): return p.capitalize()))
```

### Entity Name to Constant Name

```gdscript
func entity_name_to_const(name: String) -> String:
    # "sylvia_whistler" → "SYLVIA_WHISTLER"
    return name.to_upper()
```

## Editor Integration

The codegen is invoked from an `EditorPlugin` that adds a Tarinoi menu to
the editor toolbar:

```
Tarinoi
  └── Sync Now
  └── Regenerate Bindings
  └── Validate Bindings
  └── Plugin Settings...
```

"Validate Bindings" runs the mismatch check without writing files — useful
for CI or pre-commit checks via `godot --headless --script`.

## Generated File Header

Every generated file begins with:

```gdscript
# AUTO-GENERATED by Tarinoi codegen.
# Source: <repo_url> @ <last_synced_commit>
# Generated: <timestamp>
# Do not edit this file. Implement bindings in the impl/ directory.
```
